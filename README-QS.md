# Техническое задание (ТЗ) на проект «Max+ Quickshell Widget»

**Версия:** 1.0  
**Дата:** 2026-11-22  
**Статус:** Черновик  
**Целевая платформа:** Linux (Wayland, Hyprland)  
**Стек:** Rust (бэкенд-демон), Quickshell/QML (фронтенд-виджет), SQLite (локальное хранилище), D-Bus (IPC).

---

## 1. Общие сведения и цель проекта

### 1.1. Цель
Создать легковесный, нативный и глубоко интегрированный в среду Hyprland клиент для мессенджера Max. Клиент должен состоять из двух независимых процессов: фонового демона (бэкенд) и виджета рабочего стола (фронтенд), взаимодействующих через D-Bus. В качестве основы для работы с API Max используется существующая библиотека `rumax` (Rust).

### 1.2. Ключевые принципы
*   **Нативность:** Отсутствие веб-движков (Electron, WebView, Tauri). Только QML (QtQuick) и Rust.
*   **Энергоэффективность и легкость:** Фронтенд потребляет ресурсы только при отрисовке; бэкенд работает в фоне с минимальным потреблением CPU.
*   **Изоляция:** Падение виджета не влияет на работу демона, и наоборот.
*   **Интеграция с ОС:** Использование системных уведомлений (через `org.freedesktop.Notifications`), управление хоткеями через IPC-команды Hyprland.

---

## 2. Архитектура системы

Система делится на два основных компонента:

1.  **`maxplus-daemon` (Бэкенд):**
    *   Язык: Rust.
    *   Роль: Управление WebSocket-соединением с серверами Max (через `rumax`), шифрование/дешифрование E2E, хранение истории сообщений, кэширование аватарок и медиа, предоставление D-Bus API.
    *   Режим работы: Фоновый сервис (systemd user service).

2.  **`maxplus-widget` (Фронтенд):**
    *   Технологии: Quickshell, QML, JavaScript.
    *   Роль: Отрисовка панели (иконка с счетчиком), всплывающего окна чата, списка контактов, поля ввода. Обработка пользовательского ввода.
    *   Режим работы: Запускается композитором (Hyprland).
